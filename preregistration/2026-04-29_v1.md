## 1. 目的

光ファイバーのクラッド露出領域に PDMS が密着した際、屈折率近接（クラッド n≈1.40〜1.46 / PDMS n≈1.40〜1.43）によりエバネッセント波がクラッド外へ漏出し、伝送光量が機械的曲率変化（ベンドロス）とは独立に減少することを実験的に検証する。

副次目的：圧力センサとしての応答曲線（加重 vs 透過光量）を Phase 3 で取得し、感度・単調性を評価する。

## 2. 仮説集合

| ID | 仮説 | 主張 |
|---|---|---|
| H1 | エバネッセント結合主導 | 屈折率カップリングが支配的。剥離+PDMS で大きく落ち、ジャケット+PDMS ではほぼ変化なし。|
| H2 | ベンドロス主導 | 機械的曲率変化のみ。ジャケット有無・PDMS 組成に依存しない。|
| H3 | 機械的接触での直接変形 | PDMS 接触により局所的にファイバーが変形。光学組成不変、ジャケット依存は中間。|
| H0 | ヌル | 装置感度内で識別不能。|
| H4 | アーティファクト | 温度・接触振動・LEDドリフトが主因。条件相関より時間相関が支配的。|

H1 と H2 は共存しうる（ベンドロスの上にエバネッセント結合が重畳）が、本実験は **H1 が独立に有意な寄与を持つか** を判定する。

## 5. キャリブレーション手順

### 5.1 σ_baseline 確定（測定開始前）

1. 直線ファイバー（曲げなし、PDMS無接触、無加重）を装置に装着。
2. LED を 30 分以上ウォームアップ。
3. 連続 300 フレーム取得（fps=1、所要 5 分）。
4. 各フレームの ROI 内画素値合計を計算 → 300 値の系列。
5. σ_baseline = std(300値, ddof=1)、μ_baseline = mean(300値) を確定値として §3 と §10 に追記後、再コミット（v1.1 タグ）。

### 5.2 ROI 定義

1. 直線ファイバー装着状態で 1 フレーム取得。
2. 半自動で円検出（Hough 円検出 + 手動補正）→ 中心座標 (cx, cy) と半径 r を確定。
3. 解析 ROI は半径 r×0.8 の円内（端面エッジ揺らぎを除外）。
4. (cx, cy, r) を `analysis/roi_config.yaml` にコミット、以後変更不可。

### 5.3 ドリフト許容範囲

各セッション（Phase 1 全 6 条件 + 制御）の冒頭・中央・末尾で σ_baseline 反復測定（30フレーム）。

- 冒頭値と末尾値の差 > 2σ_baseline : セッション全体を無効化、要再測定。
- 冒頭→中央→末尾の単調ドリフト > 1σ_baseline : H4 採用候補、結果に注釈付き。

## 7. 実験フェーズ

### Phase 1 — 仮説切り分け

R=10mm 固定。条件 C-P1-01 〜 C-P1-06 を順序ランダム化して各 30 フレーム取得。前後・中央に C-CTRL-BL、冒頭末尾に C-CTRL-DARK と C-CTRL-SHAM を挟む。

完了基準：全 6 条件 + 制御を完走。データ取得不良（フレーム飛び等）が 1 条件あたり 3 フレーム以下。

想定所要時間：装着・PDMS 配置の段取り含めて 2–3 時間。

### Phase 2 — 次元スイープ

Phase 1 で D-H1-SUPPORT または D-H3-CHECK が発火した場合のみ実行。

- 曲げ半径スイープ：R = 5, 8, 10, 15, 20 mm × Phase 1 で signal が出た PDMS 条件
- 追加 PDMS：PDMS-WHITE を加える

完了基準：R 単調性のチェックが可能なデータ密度。

### Phase 3 — 加重応答曲線

Phase 2 完了かつ最大感度条件が同定された場合のみ実行。錘 0, 1, 5, 10, 50 g を 3 反復。

完了基準：応答曲線の単調性または飽和形状の決定。

## 8. バイアス対策

### 8.1 盲検化の範囲と限界

PDMS パッドの組成は外見から識別可能（透明 vs 黒）なため、組成そのものの盲検化は不可能。代替として：

- 測定順序ランダム化（§8.2）により条件配置の予測可能性を排除。
- 同一組成パッド複数枚（各組成 2 枚）作成、ID 個体識別。組成内ばらつきが組成間差を超える場合は pad-individual confound を疑う。
- 解析パイプラインは事前コミット済み（§9）であり、結果を見てから解析を変える経路を遮断。

### 8.2 順序ランダム化

```python
import numpy as np
seed = <測定直前に決定し commit>
rng = np.random.default_rng(seed)
order = rng.permutation(condition_ids)
```

シード値は `measurement/run_config.yaml` にコミットしてから測定実行。

### 8.3 シャム条件

C-CTRL-SHAM で σ_baseline の 3σ を超える偏移が出た場合、装置全体を再診断。原因特定までデータ凍結。

### 8.4 ダーク条件

C-CTRL-DARK で ROI 値が μ_baseline の 1% を超える場合、遮光ボックス漏れ。再構築要。

### 8.5 サンプル数エスカレーション

Phase 1 で (C-P1-05) − (C-P1-02) の差が 1σ < |Δ| < 3σ の中間域に入った場合、setup repetition を 3 に増やして再測定。**判定基準は |Δ| > 3σ で固定**、N を増やしても下げない。

### 8.6 生データ保全

各セッション終了時に `data/raw/<session_id>/` を tar アーカイブし SHA-256 計算、`data/raw/checksums.txt` に追記。以後の編集禁止。

## 9. 解析事前仕様

```python
# analysis/pipeline.py のロジック仕様（実装は別途、Claude Code 担当）

def analyze_condition(frames, roi_config):
    """30 フレームから条件代表値を返す。"""
    roi_sums = [integrate_roi(f, roi_config) for f in frames]
    median = np.median(roi_sums)
    mad = np.median(np.abs(roi_sums - median))
    n_outliers = sum(np.abs(roi_sums - median) > 3 * mad)
    
    return {
        "mean": np.mean(roi_sums),
        "std": np.std(roi_sums, ddof=1),
        "median": median,
        "n_outliers_3MAD": n_outliers,
        "valid": n_outliers <= 3  # 30フレーム中3超なら無効
    }

def compare(cond_a_frames, cond_b_frames, sigma_baseline):
    """Welch's t-test, two-tailed, alpha=0.01"""
    t, p = scipy.stats.ttest_ind(
        cond_a_frames, cond_b_frames, equal_var=False
    )
    delta = np.mean(cond_a_frames) - np.mean(cond_b_frames)
    return {"t": t, "p": p, "delta_sigma": delta / sigma_baseline}
```

```yaml
analysis_spec:
  alpha: 0.01
  test: welch_t_two_tailed
  outlier_flag: median_3MAD
  outlier_action: report_only        # 除外しない、再測定基準に使う
  invalid_threshold_per_condition: 3 # 30 フレーム中、3 超で条件無効
  effect_size_threshold: |delta| > 3 * sigma_baseline
```

## 10. 決定ルール

```yaml
decision_rules:
  - id: D-CRITICAL-SHAM
    condition: "C-CTRL-SHAM の |Δ| > 3 * sigma_baseline"
    action: "全データ凍結、装置診断、原因特定後に再開"
    severity: critical
  
  - id: D-CRITICAL-DARK
    condition: "C-CTRL-DARK の ROI 値が μ_baseline の 1% を超える"
    action: "遮光再構築、再測定"
    severity: critical
  
  - id: D-CRITICAL-DRIFT
    condition: "セッション内 BL 冒頭末尾差 > 2 * sigma_baseline"
    action: "セッション無効、再測定"
    severity: critical
  
  - id: D-H1-SUPPORT
    condition: |
      (C-P1-05.mean - C-P1-02.mean) > 3 * sigma_baseline AND
      (C-P1-04.mean - C-P1-02.mean) < 3 * sigma_baseline AND
      Welch p < 0.01 for (C-P1-05 vs C-P1-02)
    action: "H1 支持として Phase 2 進行"
  
  - id: D-H1-REJECT
    condition: |
      |C-P1-05.mean - C-P1-02.mean| < 1 * sigma_baseline AND
      Welch p > 0.05 for (C-P1-05 vs C-P1-02)
    action: "H1 棄却、ネガティブ結果としてレポート"
  
  - id: D-AMBIGUOUS
    condition: "1 * sigma_baseline < |Δ| < 3 * sigma_baseline (C-P1-05 vs C-P1-02)"
    action: "setup_repetitions を 3 に増やして再測定 (§8.5)"
  
  - id: D-H3-CHECK
    condition: "(C-P1-06.mean - C-P1-05.mean) < 1 * sigma_baseline"
    action: "光学組成非依存、H3 候補としてフラグ。Phase 2 進行は H1-SUPPORT または独立で signal がある場合のみ"
  
  - id: D-H0
    condition: "Phase 1 全条件で |Δ| < 3 * sigma_baseline"
    action: "H0 採用、感度限界をレポート"
  
  - id: D-PHASE2-MONOTONICITY
    condition: "Phase 2 で R 単調性が崩れる (Spearman ρ < 0.7)"
    action: "Phase 3 進行停止、診断"
```

決定ルールは Phase 1 完了後に**全部同時に**評価する。順序による有利不利を排除。
